## Integration contract for 12.2

Migration `014_notice_creation_admissions.sql` is additive and must run before the new API/frontend. A new account notice requires `POST /notice-operations` with `{}` under the normal session/CSRF boundary. The response is `{operation_id, expires_at}`. Admission is owned, payload-free, expires seven days after server issuance, and limited to 200 live unused admissions per owner. Supply that exact ID to the first `POST /notices`. Unknown, foreign, expired and purged IDs are rejected without creating anything. Accepted creates consume admission; accepted immutable account/legacy receipts remain lookup-first and retain their own notice boundary. Editing, checking and ending existing incidents keep their existing command IDs/protocol. An unaccepted pre-upgrade create with an unissued client ID is rejected; a genuinely new reviewed create must acquire admission. Existing accepted receipts remain recoverable. Coordinate migration 014 numbering when integrating 12.2; do not import its unfinished work.

Obtain admission before preparing the original create command. A failed or lost issuance response keeps the proposal and requires an explicit new save attempt; it never dispatches a create. Once a create may have dispatched, retain the original command and ID and use receipt lookup before any retry. A new ID must never be substituted during recovery. Existing frontend seed consumers and the explicit create in `verify-private-drafts.py` were adapted; its orchestration was not executed.

Drafts remain creation + seven days. Plans retain the minimum of planned end + seven days and terminal server end + seven days. Notices remain independent account resources until effective ending + seven days, including accepted legacy handling. No day-cascade or sliding renewal was introduced. Lists recheck retention after final authorization and retain scan continuation when rows expire inside a page. Notice reader projection uses the same final database instant as `server_now`. Detail reads recheck authority before returning.

Private session/draft/plan/resource expiry uses a shared memory-only clock advanced from exposed HTTP Date and precise notice server_now by monotonic elapsed time. Timers recheck their original deadlines; a frozen/slow device clock cannot prolong retained presentation. Known expired saved manual/imported draft fields and notice editor/comparison/original-command/reader payloads are removed and late callbacks invalidated. Unrelated fresh unsaved proposals survive. Notice validity ending still permits read-only history until its independent storage deadline. No browser persistent private store, raw-PDF archive or new payload log was added.
