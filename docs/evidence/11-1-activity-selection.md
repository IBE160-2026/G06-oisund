## Delivered behavior

Selection stores exact confirmed member IDs independently of the immutable snapshot, physical bus and lifecycle. Initial current selection is null/revision zero. Direct choices and previous/next follow confirmed order, preserving equal-time order and overnight dates, including individual grouped pause members and non-passenger work. Gaps are excluded. Passenger labels show type/line/direction/destination/Oslo date/time; other activity labels retain type/time, known relevant places and applicable identifiers without inventing missing routes for reporting/pauses. Shared direct/selected label semantics, manual wording and textual member markers distinguish saved state from retained proposals.

Start is a separate explicit action available with or without selection. Missing lifecycle means confirmed/not started/revision zero. The first accepted start records active/revision one and authoritative server `started_at`. Same-operation replay preserves its receipt; different start operations on an already active plan converge on the same timestamp and lifecycle revision. Planned first activity start and actual registration remain separately labelled. Neither operation changes source facts, accepted review policy, physical bus, outcomes or expiry.

Both resources enforce typed UUID/revision bodies, server ownership/session checks, fixed expiry and operation fingerprints inside the existing account/plan transaction locks. Final session/expiry failures roll back effect and receipt together. Parent deletion/expiry cascades resources/receipts. Each resource admits at most 2,000 live receipts per account, while accepted replay bypasses admission. Current lifecycle authority remains separate from historical confirmation records.

The browser keeps uncertain operations/proposals only in memory. Check/same-body retry validates receipts and then current authorized state. Older accepted receipts cannot revert newer selection. Stale writes offer explicit comparison/reload. Validated capacity rejection permits explicit retry/cancel; unrecognized errors stay unresolved. Independent child locks/availability aggregate so one successful child cannot release another unresolved guard or hide its denial. Account changes/expiry clear presentation and discard stale replies. Acknowledged choice/start moves keyboard focus to its status.
