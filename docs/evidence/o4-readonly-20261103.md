# O4 lesende driftskontroll 3. november 2026

`origin/main` var `4a848c8` etter ny fetch. Produksjonens driftsstatus over SSH viste release `7921eb54e4816aaab9368c3efd851bcf692f3823` med friske API- og databasecontainere og aktiv Cloudflare-tunnel.

| Kontroll | Observasjon |
|---|---|
| Bindinger | SSH på alle vertsgrensesnitt på TCP 22. Gateway 18081 og tunnelmetrics 18083 på loopback. API, gate og database har ingen publiserte vertsporter. Resolver og NTP lytter lokalt. Fire UDP-sokler på wildcard med høye porter ble observert. Prosesseier og filtrering kunne ikke bekreftes uten administratorlesing. |
| Ruter | Wi-Fi har privat IPv4 med standardrute via lokal ruter. IPv6 på serveren har ULA og link-local, uten offentlig global adresse eller standardrute. Linux rapporterer IPv4-videresending på og global IPv6-videresending av. Dette er vertsinnstillinger. |
| LAN og direkte origin | Tidligere LAN-prøver gjenbrukes med bekreftet uendret adresse og bindinger. SSH svarte over IPv4 og IPv6 ULA. TCP 18081, 18083, 8000, 5432 og 8081 ga timeout. Ny `bussassistentctl check` bekreftet frisk API og avslag mot origin uten autentisering. |
| Cloudflare-ruten | HTTPS GET mot offentlig app via IPv4 fra PC-en ga 302 ved Access. DNS svarte med Cloudflare AAAA. Tvunget IPv6-kall fra PC-en ga curl-feil 6 og ingen HTTP-status. Ingen IPv6-standardrute ble listet på PC-en. Dette gir ingen uavhengig WAN-måling. Cloudflares adresser var aldri mål for direkte origin-prøver. |
| Brannmur | Lesing av UFW, nftables, iptables og ip6tables med `sudo -n` krevde interaktiv administratorautentisering. Effektive regler er uavklart. |
| Ruter og ekstern måling | Autorisert ruterøkt, bekreftet egen direkte WAN-adresse og uavhengig autorisert målepunkt mangler. WAN-kontroller er uutført. |

O4 står åpen. Lukkekriteriene krever effektive brannmurregler, ruterens NAT-/videresendingsregler og IPv6-policy samt uavhengig kontroll av bekreftet egen WAN-eksponering. Hvis ruteren bekrefter at serveren ikke har en offentlig routbar IPv6-adresse, dokumenteres dette med ruter- og vertsbevis. En direkte IPv6-test krever et faktisk mål. Ingen konfigurasjon ble endret.

For å avklare restpunktene kan administrator kjøre `sudo ufw status verbose`, `sudo nft list ruleset` og `sudo ss -H -lunp` på Ubuntu. Rutervisningen må dekke portvideresending, DMZ, aktive UPnP-regler, WAN-adressetype og IPv6-brannmur. Bruk deretter et autorisert nett utenfor hjemmenettet til avgrensede prøver mot bekreftet egen adresse.
