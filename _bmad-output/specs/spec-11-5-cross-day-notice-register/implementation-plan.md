1. Introduce one canonical account-owned registry with an additive versioned migration. Prefer evolving existing incident rows with backfilled owner and independent retention, nullable original-workday provenance using SET NULL, stable IDs and preserved original fields. New account command receipts have independent ownership/retention, expected notice revisions and explicit payload identities. Account deletion cascades; original workday deletion/closure cannot remove or shorten global notices or new receipts.
2. New registrations require `valid_until` (or an explicit equivalent ending field) resolved by authoritative server Oslo rules. Retain source update/valid-from as nullable and never infer source verification. For date-only ending, visibly default to the end of that Oslo date; an explicitly entered clock overrides it. Atomic checks use the server clock under the existing account/record lock: registered and now before current end for save/extension/check/manual end. Earlier manual end is terminal. Expired and manually ended entries are read-only and cannot be revived by edits, replay, old accepted receipts or delayed calls. Effective expiry is distinct from manual status and source check. Retain seven days after effective ending, shorten for early manual end, and purge independently of days. Accepted historical effects remain immutable; lookup also checks live current resource/retention before return.
3. Migration never deletes existing ordinary records or fabricates validity. Old unknown-end incidents show `Mangler sluttdato`, retain their original storage deadline and can receive their first explicit future end before storage expiry; exclude them from active relevance until completed. Dated legacy incidents become shared with their exact current content/ID. Already ended/past legacy rows receive at least a one-time seven-day migration read-only grace; do not revive them. Preserve historical receipts byte-for-byte, including old payload hashes/results. Do not deduplicate the owner's separately entered duplicates by guessing identity.
4. Management is an account resource available independently of an open/live shift, including from closed shifts. Keep separate reader/maintenance/editor screens. Retain the registry controller above plan replacement/expiry so source text and original pending commands survive day navigation. Integrate its dirty/pending guard into existing workspace navigation/loss/security controls. Reuse 11.6 `recoverOperation` with account registry lookup/current callbacks. A denied or expired day may hide that day reader; it must not invalidate the independent incident. Account/session loss still clears all private state. Browser timers hide/qualify expired entries while the page stays open, using server-derived time/revalidation; no client deadline override or automatic source fetch.
5. Reader authenticates the displayed plan, then projects that owner's active dated notices using existing exact line/all-line and planned Oslo interval rules. It returns each incident once. Notice ID/content/check state are shared across all days; response access lease (the plan) must be separate from each notice retention. Manual-ended/expired entries disappear from active reader and remain qualified in registry history. Unknown source start remains partial/uncertain; no clear-road, current-trip or completeness claim.
