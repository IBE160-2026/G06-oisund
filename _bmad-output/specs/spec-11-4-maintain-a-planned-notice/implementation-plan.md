## Implemented user flow and copy

The owner's correction updates the flow below: title plus optional short/deep text, optional source description/URL and explicit specific/all-line selection. Specific lines are required only in specific scope; switching scope retains the user's local tag proposal. SMS-only entries need no invented link. The [corrective dispatch specification](../../implementation-artifacts/spec-11-4-real-notice-sources.md) records current compatibility and verification; earlier full-gate results remain historical.

1. **Day:** Add a secondary `Manuelt vedlikeholdte avvik` destination for the displayed confirmed day. Keep bus, activity list and existing Start/End navigation. No notice form/list is stacked under the activity detail. Returning restores the saved selection and does not send another selection write.
2. **Management list:** Open a separate screen headed `Manuelt vedlikeholdte avvik`, with service date/day context, `Tilbake til dagen`, `Registrer avvik` and individually identified records. This is an unfiltered management list of records attached to this day, including manually ended records. Show all entered tags without saying they match this day. A shared 20/24 record is one stored item; two independently entered incidents remain two items. 11.5 owns the relevance reader.
3. **New/edit:** Open a separate screen with required title, optional short explanation, multiline detailed explanation, source description and URL. Explicitly choose specific lines with tags or `Alle linjer`; never derive all-lines from missing input. Scope changes preserve the local specific-line proposal. Optional source-update/validity timestamps remain unknown when blank, without current-clock defaults. Use the existing Oslo resolver for known times/DST. Show `Lagre avvik`, `Tilbake til avvik` and explicit discard. New notices start as `Registrert` without requiring shift Start; SMS-only sources need no URL.
4. **Saved detail:** After a validated acknowledgement, return to management with the saved detail expanded and meaningful focus. Display title, complete short/deep explanations, selected/all scope, optional source description/link, manual status, known/unknown validity, source update, entry/edit/check times. Preserve multiline instructions with pre-wrap. Null-time labels remain explicit; registration/edit times never substitute for source time.
5. **Explicit checking:** The source link opens as an ordinary link without recording a check. After manually inspecting the source, use `Kontrollerte kilden nå` on saved current content. Explain that this records the user's check time, not automatic verification or coverage. Disable a fresh check while the editor is dirty or another command is unresolved. Persist the server check time only on acknowledgement. Later edits keep the previous check visibly labelled `Kontrollert før siste endring` until another check.
6. **Manual ending:** A distinct `Avslutt avvik manuelt` action asks for explicit confirmation with clear cancel, then saves `Avsluttet manuelt`. Cancel makes no request. Keep the ended record visible and source metadata editable while the workday remains mutable; checks still require an explicit action. Ending the notice does not end the shift. No clock/source disappearance automatically changes status. Reopening/deleting a notice is outside this slice.
7. **Back/cancel/failure:** Safe screen switching preserves local forms and original unresolved commands above hidden screens. Returning to an unsaved editor restores its values; explicit discard restores the last acknowledged record (or removes only the unsent new proposal). Closing the plan, changing displayed day, deleting or closing the shift must use aggregate loss/pending guards and direct the user to reachable recovery. Warn before page loss; reload recovers only authorized server-saved state. A pending command cannot be discarded as known-failed.
8. **Closed/reopened day:** Existing recap remains the initial terminal destination. From read-only day consultation, notices remain readable until expiry, with no fresh edit/check/end actions. Old accepted receipt results reconcile with current terminal/deadline authority and never restore editing. Logout/session expiry clears private presentation; suspended access hides retained proposals pending revalidation as it already does elsewhere.

Empty state: `Ingen avvik er registrert her. Kontroller originalkilden.` Unavailable state: `Avvikslisten er utilgjengelig. Prøv igjen eller kontroller originalkilden.` Retained old data, if shown, is explicitly unrefreshed; a failed read never becomes an empty-list success. No claim of precise activity relevance or a clear route.

## Implemented state and data contracts

| Workday state | Read notices | New/edit/check/manual ending |
|---|---|---|
| Confirmed, not started | Authorized within retention | Allowed explicitly; never Starts the shift |
| Active | Authorized within retention | Allowed explicitly |
| Ended / aborted | Authorized read-only within retention | Fresh writes rejected server-side |
| Suspended / denied / deleted / expired | Existing private visibility/access rules | No assumed authority; no resurrection |

Additive migration `backend/migrations/private/011_manual_notices.sql` introduces notices and immutable accepted-operation receipts. Each notice has UUID, parent workday ID, revision, title, explicit line tags, source URL, nullable `source_updated_at`, nullable `valid_from`/`valid_until`, explicit `registered | ended_manually` status, first server `entered_at`, server `edited_at`, nullable `checked_at` and nullable `checked_revision`. A check advances the notice revision and binds checked_revision to the resulting saved revision; later edits advance revision without manufacturing another check. Initial check fields are null. Rendering compares the saved/check revisions to qualify a prior check. No private content history is needed.

Implemented technical bounds: title 300 characters, optional summary 1000, optional detailed text 5000, optional source description 500, optional URL 2048, 50 unique tags of 300 characters, 200 notices/workday and 2000 live receipts/account. Migration 012 adds the nullable text fields and selected/all scope; existing rows become selected with null added text, while existing content/receipts remain unchanged. Selected requires tags; all requires an empty persisted tag list and explicit user selection. Reject invalid types, NUL/unsupported controls, lone surrogates and nonempty non-HTTP(S) links. Detailed text allows line breaks/tabs; preserve valid astral Unicode and explicit identifiers such as `020`. Trim surrounding whitespace and deduplicate exact tags, without inferred route-number extraction. Quoted CSV preserves literal commas/quotes. Validity/source-update fields independently support null and known bounds must be ordered; server Oslo serialization/resolution remains authoritative.

Implemented API names:

| Operation | Contract |
|---|---|
| List/read | `GET /workdays/{id}/notices` (bounded pagination), `GET /workdays/{id}/notices/{notice_id}`; parent identity/current expiry plus validated records |
| Create/update | `POST /workdays/{id}/notices` and `POST /workdays/{id}/notices/{notice_id}`; operation UUID, explicit content, expected notice revision (zero for create), expected lifecycle revision |
| Check | `POST /workdays/{id}/notices/{notice_id}/check`; stable operation UUID and expected notice/lifecycle revisions; no client-supplied checked-at |
| End manually | `POST /workdays/{id}/notices/{notice_id}/end`; stable operation UUID and expected notice/lifecycle revisions; never infer from validity |
| Resolve uncertain command | `GET /workday-notice-operations/{operation_id}`; authorized immutable receipt, followed by current parent/notice reconciliation |

Bind create's notice identity to the original command so retries cannot create another row. All mutations serialize through `workday_storage.owned` and the workday lock; derive ownership from the session, validate parent membership and expected revisions, use `require_mutable`, and recheck session/expiry at atomic acceptance. Save content/status/check effect and receipt in one transaction. Same operation and payload returns the original accepted effect; a changed payload/target conflicts. Repeated fresh end of an already-ended notice cannot claim a new status transition. Read-only historical lookup may resolve a prior accepted effect after closure only while current access/expiry allows it. Current terminal state always wins over old receipt data.

Source text remains plain text, links remain HTTP(S) and new-tab links use the existing safe rel pattern. There is no backend URL fetch/preview. Use meaningful existing 401/403-or-404/409/410/422/429 responses and private no-store. Validate returned notice ID/workday/content/revision/timestamps before saved feedback; HTML/malformed/late replies do not establish success. Bind commands and callbacks to displayed account/session and workday, using existing private wrappers. Do not let a delayed reply navigate away from a screen the user subsequently chose.
